## 🚀 Projects

### 📚 [LibraryTools](https://github.com/Matthew2077/LibraryTools) — *Completed*
An API-first backend for managing and structuring knowledge through notes, categories, and tags. This was my first real project built without a tutorial holding my hand — the proving ground where I learned to choose my own stack, wire up new libraries, and actually design something meant to grow over time.

- **Stack:** Python, FastAPI, SQLAlchemy, Pydantic
- **Highlights:**
  - Full CRUD for notes, categories, tags, and users
  - Note status management (draft, published, archived)
  - Many-to-many relationship mapping between notes and tags
- 📄 [Technical review (v1.0)](https://github.com/Matthew2077/LibraryTools/blob/main/v1_review.md)

### 🗡️ [Katana](https://github.com/Matthew2077/Katana) — *Completed*
Same stack as LibraryTools, built in a tight ~5-day sprint. Less about the final product, more a testbed for architecture patterns, error handling, and structured logging — the lessons here fed straight back into improving LibraryTools.

- **Stack:** Python, FastAPI

### 🤖 [TeleLibrary](https://github.com/Matthew2077/TeleLibrary) — *In Progress*
An interactive Telegram bot that consumes the LibraryTools API directly — letting users view their own, public, or shared notes, and create, edit, and share notes from inside Telegram.

The idea grew out of a real need: as a moderator in a Telegram group, I kept writing guides for people and wanted an easier, more structured way to share them.

This project is where I've leveled up my process the most — I'm reasoning in terms of a feedback loop (thinking about how to test code *as* I write it, not after), documenting the system as I go, and making much more deliberate architectural decisions instead of just pushing forward.
